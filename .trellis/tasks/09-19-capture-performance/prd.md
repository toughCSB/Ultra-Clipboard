# 캡처 및 앱 반응속도

## Goal

캡처 시작의 깜빡임과 체감 지연을 제거하고 주요 반응 경로에서 확인된 병목을 개선한다.

## Background

- 캡처는 화면 복사 → 세션 저장 → 숨긴 오버레이 준비 → 바이너리 IPC → createImageBitmap/canvas 그리기 → 표시 순서다.
- 오버레이는 첫 사용 때 생성하고 이후 재사용한다. 표시 직후 bounds를 다시 적용한다.
- 목록은 react-virtuoso와 30행 페이지·180행 캐시를 사용한다. 검색은 FTS5 또는 LIKE 경로다.

## Requirements

- 캡처의 실제 원인을 코드와 실행 관찰로 구분하고 확인된 원인에 집중해 수정한다.
- 앱 시작~창 표시, 단축키, 목록 렌더링, DB 쿼리·인덱스, 검색, 이미지 썸네일, IPC·폴링·타이머를 점검한다.
- 측정 가능한 변경은 전후 수치를 남긴다. 근거 없는 미세 최적화와 위험한 스키마 변경은 피한다.
- 기존 Windows/macOS 경로와 사용자 데이터 경계를 지킨다.

## Acceptance Criteria

- [x] 캡처 원인을 코드 근거와 수정 전 Rust 측정값으로 설명한다.
- [ ] 수정 후 캡처 시작·취소·재시도·다중 모니터 시각 검증은 남았다.
- [x] 나열된 앱 경로의 점검 결과를 수치 또는 정적 근거와 함께 보고한다.
- [x] 스키마 변경은 없으며 신규 마이그레이션도 필요하지 않다.
